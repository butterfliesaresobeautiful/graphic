# ЛБ2 — Программа для формирования изображений

Вариант **28 % 20 = 8**: перенос круга из левого нижнего угла источника в верхнюю центральную часть нового изображения; график **y = x³**. 


## Запуск без Go

Скачать ZIP, распаковать в доступную для записи папку и открыть терминал в `lab2-variant8`:

```bash
chmod +x bin/lab2-linux-amd64
./bin/lab2-linux-amd64
```

Для Linux ARM64 (`uname -m` показывает `aarch64`) использовать `bin/lab2-linux-arm64`. Для обычного Intel/AMD (`x86_64`) — `lab2-linux-amd64`.

Это настоящее десктопное окно. Нужен графический сеанс **X11 или XWayland** с установленным `DISPLAY`, стандартным TrueColor-экраном (32-битное представление пикселя). В обычном локальном сеансе переменные доступа к экрану уже настроены. Из чистой консоли без графической среды можно выполнить пакетную обработку. Go, Python, браузер, сервер, интернет и системные шрифты для запуска приложения не нужны: оба ELF статические, шрифт встроен. Сборка amd64 проверена запуском; arm64 собрана перекрёстно, но на ARM не исполнялась.

Если файловый менеджер предлагает открыть файл редактором, запускать приведённой командой из терминала. При `Permission denied` проверить право исполнения и перенести комплект с файловой системы, смонтированной с `noexec`, в домашний каталог. Сообщение о невозможности соединиться с X означает отсутствие доступного графического сеанса; запускать из терминала своего рабочего стола либо использовать `-mode batch`.

## Действия в окне

1. Нажать **«Создать холст»**: появится белое изображение выбранных ширины и высоты.
2. Нажать **«Открыть файл…»** и выбрать PNG, JPEG или GIF. Уже созданный холст сохраняется; старые производные этапы сбрасываются. Кнопка **«Демо»** устанавливает встроенный испытательный рисунок.
3. Нажать **«Перенести круг»**, затем **«Добавить оси»**, затем **«Построить y = x³»**.
4. Указать папку в поле **«Каталог PNG»** или через **«Выбрать каталог…»**. Нажать **«Сохранить PNG»**: последний выполненный этап будет записан в `result.png` этой папки. По умолчанию это `output` рядом с папкой `bin`.

**«Выполнить всё»** выполняет расчёт всех этапов сразу. Кнопка представления справа переключает пару «источник и результат» на обзор четырёх этапов; она не изменяет сохраняемый результат. Для сохранения промежуточного этапа нажать «Сохранить PNG» сразу после соответствующего действия. Для выгрузки всех этапов одним запуском использовать пакетный режим ниже.

Числовое поле заменяется первым введённым символом после фокуса; доступны Backspace и Enter. В файловом диалоге путь можно редактировать, переходить в папки и выбирать файл. Изменения чисел применяются при создании, переносе или полном расчёте. Изменённые размеры требуют создания нового холста. Оси и график используют параметры уже выполненного переноса, поэтому частично отредактированные поля не повреждают результат.

Автоматические позиции соответствуют варианту 8. При `R=70`, источнике `800×600` и холсте `1000×720`: исходный центр `(70,529)`, новый `(500,70)`, перенесено **15373** пикселя без отсечения. Автоматический режим требует, чтобы круг целиком помещался в левой нижней четверти источника и в новом холсте. Для источника `800×600` предельный автоматический радиус — 149.

Кнопка **«Позиции: вариант 8»** включает ручной режим для экспериментов с центрами и отсечением. При ручном размещении пользователь отвечает за соответствие варианту и разнесение круга с графиком. Ошибки показываются в строке состояния; предыдущий корректный результат сохраняется.

## Пакетный режим без графического сеанса

```bash
# Встроенный рисунок и все этапы:
./bin/lab2-linux-amd64 -mode demo -out output

# Обработка своего файла:
./bin/lab2-linux-amd64 -mode batch -source images/source.png -out output

# Другие размеры и радиус, позиции автоматически по варианту:
./bin/lab2-linux-amd64 -mode batch -source images/source.png \
  -width 1200 -height 900 -radius 100 -out output-large

# Явные центры для исследования граничных случаев:
./bin/lab2-linux-amd64 -mode batch -source images/source.png \
  -auto=false -sx 70 -sy 529 -dx 500 -dy 70 -radius 70 -out output-manual

./bin/lab2-linux-amd64 -help
```

Создаются `source.png`, `blank.png`, `transferred.png`, `axes.png`, `result.png`, `metrics.json`. `source.png` — декодированный непрозрачный RGB-источник; прозрачность накладывается на белый фон, у GIF читается первый кадр. Каждый подходящий пиксель круга копируется без интерполяции. PNG сохраняет эти значения без потерь. Превью в окне масштабируется только для отображения.

Ограничения: стороны до 4096 и до 16 миллионов пикселей, входной файл до 32 МиБ, радиус 1–2048, координаты центров −8192…8192. Для осей и графика проверяется наличие места ниже круга. Слишком маленькое изображение или чрезмерный радиус вызывают понятную ошибку. Исходный файл защищён от перезаписи, включая совпадение через символическую или жёсткую ссылку. PNG записываются атомарно по одному; набор файлов целиком не является атомарной транзакцией.

## Содержимое комплекта

- `bin/` — готовые Linux amd64/arm64 файлы, не требующие Go.
- `cmd/lab2/`, `internal/imaging/`, `internal/desktop/` — исходники и тесты Go.
- `vendor/`, `third_party/` — зависимости, встроенный шрифт и лицензии.
- `images/` — воспроизводимые исходник, четыре этапа и числовые результаты.
- `report/` — DOCX, PDF, Markdown, блок-схемы SVG/PNG, настоящие снимки окна, манифест.
- `reference/` — неизменённые страницы методички.
- `validation/` — журналы тестов, ELF, запуска без Go, проверки отчёта и ZIP.
- `tools/` — вспомогательные Python-скрипты оформления, проверки и упаковки; приложение их не использует.
- `SHA256SUMS` — контрольные суммы файлов комплекта; архив не включён в собственный манифест.

## Разработка и воспроизведение проверок

Этот раздел нужен только для изменения программы. Для запуска готового приложения он не требуется.

```bash
# Go 1.22 или новее, зависимости уже в vendor:
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -mod=vendor -trimpath \
  -ldflags='-s -w' -o bin/lab2-linux-amd64 ./cmd/lab2
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -mod=vendor -trimpath \
  -ldflags='-s -w' -o bin/lab2-linux-arm64 ./cmd/lab2

go test -mod=vendor -count=1 -v ./...
go vet -mod=vendor ./...
```

Полный прогон выполнен с Go 1.27.3. **10 тестов пройдены**, включая реальное окно X11. Без `DISPLAY` нативный оконный тест явно пропускается. Чтобы проверить готовый бинарник в отдельном Xvfb-сеансе:

```bash
Xvfb :99 -screen 0 1440x1080x24 -nolisten tcp &
DISPLAY=:99 LAB2_GUI_BINARY="$PWD/bin/lab2-linux-amd64" \
  LAB2_GUI_CAPTURE="$PWD/report/interface.png" \
  LAB2_GUI_COMPARISON="$PWD/report/interface-stages.png" \
  go test -mod=vendor -count=1 -v ./...
```

Тест оконного запуска использует `PATH=/nonexistent`, вводит ширину, создаёт холст, открывает файл через диалог, выполняет три преобразования, сохраняет PNG и сравнивает все пиксели с ядром. В отдельной трассировке пакетного запуска нет дочерних программ и сетевых соединений. Это проверка отсутствия зависимости от Go при исполнении, а не утверждение, что Go удалён с машины сборки.

Для пересборки отчёта нужны Python с `python-docx`, Pillow, PyMuPDF; Inkscape для схем; LibreOffice и Times New Roman для PDF:

```bash
python tools/build_diagrams.py
python tools/build_report.py
soffice --headless --convert-to pdf --outdir report report/report.docx
python tools/check_report.py
python tools/package.py
sha256sum -c SHA256SUMS
```

Скрипт проверки сверяет весь листинг в DOCX/PDF.  Упаковщик извлекает ZIP заново, проверяет CRC и все SHA256, запускает amd64 без Go в PATH и сравнивает пять PNG и JSON с опубликованными результатами.
