# ЛБ8 — Интерполяция изображений

**Готовый комплект:** [ZIP](dist/lab8.zip) · [Отчёт DOCX](report/report.docx) · [Отчёт PDF](report/report.pdf).

Выполнено общее задание приложенного [ЛР8.docx](reference/ЛР8.docx): масштабирование, поворот и скос с разными параметрами с применением ближайшего соседа, билинейной и бикубической интерполяции. Индивидуальный номер **28**. Угол 28° — выбранный параметр одного опыта.

## Запуск на Linux без Go

Скачать ZIP, распаковать в доступную для записи папку, открыть терминал в `lab8`:

```bash
chmod +x bin/lab8-linux-amd64
./bin/lab8-linux-amd64
```

Для Linux ARM64 (`uname -m` показывает `aarch64`) использовать `bin/lab8-linux-arm64`; для обычных Intel/AMD (`x86_64`) — amd64. Бинарники статические, шрифт встроен. **Go, Python, браузер и интернет для запуска не нужны.** AMD64 проверен выполнением; ARM64 собран перекрёстно и проверен по ELF, но на ARM не исполнялся.

Для настоящего десктопного окна нужен **X11 или XWayland**, доступный `DISPLAY` и обычный TrueColor-экран с 32-битным представлением пикселя. Запускать из терминала собственного графического сеанса. При `Permission denied` проверить право исполнения и отсутствие `noexec` у файловой системы. При отсутствии графического сеанса использовать пакетный режим ниже.

## Работа с приложением

1. **«Открыть файл…»** — выбрать PNG, JPEG или GIF. **«Демо»** — встроенный рисунок с градиентами, сеткой, тонкими линиями и цветными полосами.
2. Задать **Sx, Sy**, угол в градусах, скосы **hx, hy**. Допускаются десятичная точка и запятая в окне. Кнопка **«Набор …: следующий»** циклически выбирает восемь подготовленных опытов, начиная с тождественного.
3. Нажать **«Преобразовать»**. Источник и три результата видны одновременно. Применяется последовательность **масштаб → одновременный скос по двум осям → поворот**, за один проход интерполяции. Положительный угол поворачивает по часовой стрелке.
4. **«Пиксели»** — центральный фрагмент каждого изображения, увеличенный без сглаживания. Координаты ROI подписаны; три результата сравниваются на одном участке. Центр источника — самостоятельный фрагмент, он не совмещён обратным преобразованием с результатом.
5. Указать каталог в поле или через **«Выбрать папку…»**, нажать **«Сохранить всё»**. По умолчанию папка `output` находится рядом с `bin`.

После изменения параметров нужно нажать «Преобразовать»: сохранение использует последний успешный расчёт. Ошибка оставляет предыдущий результат; новый источник сбрасывает прежние результаты. В строке состояния показываются параметры выполненного расчёта и число ограниченных каналов бикубического метода.

В числовых полях первый символ после выбора заменяет прежнее значение. Доступны Tab, Backspace, Ctrl+A, Enter (расчёт), Esc (закрыть файловый диалог). В диалоге можно вводить путь, переходить по папкам и выбирать файл; длинные списки имеют страницы и прокрутку колесом.

## Пакетная обработка без экрана

```bash
# Пример со стандартным составным преобразованием:
./bin/lab8-linux-amd64 -mode demo -out output

# Свой файл, только масштабирование:
./bin/lab8-linux-amd64 -mode batch -source photo.png \
  -sx 1.7 -sy 1.4 -angle 0 -hx 0 -hy 0 -out output-scale

# Только поворот:
./bin/lab8-linux-amd64 -mode batch -source photo.png \
  -sx 1 -sy 1 -angle 28 -hx 0 -hy 0 -out output-rotation

# Только скос:
./bin/lab8-linux-amd64 -mode batch -source photo.png \
  -sx 1 -sy 1 -angle 0 -hx 0.45 -hy 0.15 -out output-shear

# Все восемь опытов со встроенным рисунком:
./bin/lab8-linux-amd64 -mode suite -out experiments

# Те же восемь опытов со своим источником:
./bin/lab8-linux-amd64 -mode suite -source photo.png -out experiments-own

./bin/lab8-linux-amd64 -help
```

В CLI дробные числа задаются с точкой. В режиме `suite` используются фиксированные наборы, а не флаги отдельных преобразований. В остальных режимах по умолчанию: `sx=1.25`, `sy=0.9`, `angle=28`, `hx=0.25`, `hy=-0.1`. Чтобы выполнить только одно преобразование, остальные параметры нужно явно установить в единичные/нулевые значения, как в примерах.

Каждый расчёт сохраняет `source.png`, `nearest.png`, `bilinear.png`, `bicubic.png`, `metrics.json`. В `suite` каждому опыту соответствует отдельная подпапка. PNG не теряют значений RGB. Входная прозрачность накладывается на белый фон; у GIF читается первый кадр. Исходник защищён от перезаписи, включая совпадение через ссылки. Каждый PNG записывается атомарно, весь набор — последовательно.

## Параметры опытов

| Папка | Sx | Sy | Угол | hx | hy | Выход для 480×360 |
|---|---:|---:|---:|---:|---:|---|
| `identity` | 1 | 1 | 0° | 0 | 0 | 480×360 |
| `scale-up` | 1.7 | 1.4 | 0° | 0 | 0 | 816×504 |
| `scale-down` | 0.55 | 0.65 | 0° | 0 | 0 | 264×234 |
| `rotate-positive` | 1 | 1 | 28° | 0 | 0 | 593×544 |
| `rotate-negative` | 1 | 1 | −17° | 0 | 0 | 565×485 |
| `shear-positive` | 1 | 1 | 0° | 0.45 | 0.15 | 642×432 |
| `shear-negative` | 1 | 1 | 0° | −0.35 | 0.10 | 606×408 |
| `combined` | 1.25 | 0.9 | 28° | 0.25 | −0.1 | 639×553 |

Ограничения: масштаб 0.05…8, угол −360…360°, скосы −3…3, `|1−hx·hy| ≥ 0.01`; стороны источника и результата до 4096, площадь до 16 миллионов пикселей, файл до 32 МиБ. Крупные изображения обрабатываются дольше; предыдущий расчёт отображается до завершения нового. Для источника 1×1 и сильного уменьшения возможна ошибка пустого покрытия.

## Алгоритмы и исправления в документе

Все три метода используют одну обратную матрицу, одинаковые координаты центров пикселей, холст по преобразованным углам и общую маску покрытия. Опорные точки у границы повторяют крайний пиксель; точки вне преобразованного прямоугольника остаются белыми. Самостоятельно реализованы 1, 4 и 16 опорных отсчётов соответственно.

Бикубический метод — **тензорный кубический Лагранж на узлах −1, 0, 1, 2**. В перечне коэффициентов исходного документа перепутаны отдельные координаты/знаки; в `c14` стоит `xy` вместо `ab`. Например, при `a=0, b=0.5` коэффициент `f(l,k+1)` должен быть `9/16`, а напечатанный `c2` даёт ноль. Реализация использует согласованное произведение одномерных весов; это подробно объяснено в отчёте, оригинал документа сохранён без изменений. Не используется подмена на Keys/Catmull–Rom.

Отрицательные веса кубики могут давать выбросы, поэтому каналы ограничиваются диапазоном 0…255. `ClippedChannels` считает каналы, не пиксели. `Differences` содержит MAE, RMSE, максимальное различие и число разных пикселей **внутри общей маски**. Это различия методов, а не ошибка относительно известного эталона. При тождественном преобразовании все результаты точны; при составном MAE NN–BL = 6.4572, MAE NN–BC = 7.5041, RMSE BL–BC = 4.6049.

Интерполяция выполняется по 8-битным кодам RGB без линеаризации гаммы и цветовых профилей. Предварительного низкочастотного фильтра нет: при уменьшении возможно наложение частот у всех трёх методов. Эти ограничения и наблюдаемые артефакты разобраны в выводах.

## Отчёт и материалы

- `report/report.docx`, `report.pdf`, `report.md` — полный отчёт, собственный код с тестами, две блок-схемы, 12 иллюстраций, таблицы восьми опытов и выводы.
- `report/interface*.png` — реальные снимки X11, а не макеты.
- `images/` — результаты всех восьми опытов, PNG и JSON.
- `reference/ЛР8.docx` — неизменённое задание; `report-format.json` — параметры оформления ЛБ4/ЛБ6.
- `validation/` — тесты, ELF, автономный запуск, проверки отчёта/оформления/архива.
- `vendor/`, `third_party/` — зависимости и лицензии; для сборки скачивание модулей не нужно.

## Разработка и воспроизведение

Для запуска готовых бинарников этот раздел не нужен. Для изменения исходников требуется Go 1.22+; комплект проверен с Go 1.27.3.

```bash
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -mod=vendor -trimpath \
  -ldflags='-s -w' -o bin/lab8-linux-amd64 ./cmd/lab8
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -mod=vendor -trimpath \
  -ldflags='-s -w' -o bin/lab8-linux-arm64 ./cmd/lab8

go test -mod=vendor -count=1 -v ./...
go vet -mod=vendor ./...
```

```bash
Xvfb :99 -screen 0 1440x1080x24 -nolisten tcp &
DISPLAY=:99 LAB8_GUI_BINARY="$PWD/bin/lab8-linux-amd64" \
  LAB8_GUI_CAPTURE="$PWD/report/interface.png" \
  LAB8_GUI_COMPARISON="$PWD/report/interface-zoom.png" \
  go test -mod=vendor -count=1 -v ./...
```
