# Лабораторная №6 — Геометрические преобразования

Индивидуальный номер **28**, максимум в таблице — **20**, вариант **28 % 20 = 8**.
Задание: **поворот, отражение; i = x′^(5/3), j = y′**.

## Запуск без Go

Распакуйте `dist/lab6-variant8.zip` в доступный для записи каталог. Откройте терминал в распакованной папке `lab6-variant8` (или в `lb6` репозитория):

```bash
chmod +x bin/lab6-linux-amd64
./bin/lab6-linux-amd64
```

Это самостоятельное настольное окно с русским интерфейсом. Демонстрационное изображение доступно сразу. Go, Python, браузер, интернет, GTK/Qt и библиотеки разработки для запуска не нужны. Шрифт встроен в бинарник.

Нужен обычный графический сеанс Linux **X11 либо Wayland с XWayland**, с доступным `DISPLAY` и TrueColor (32 бита хранения пикселя, порядок LSBFirst). Приложение сообщает ошибку, если такой экран недоступен. Не запускайте его через `sudo`: это может закрыть доступ к пользовательскому экрану. Для терминального сервера без экрана предусмотрен `batch`.

Для ARM64/AArch64 используйте `./bin/lab6-linux-arm64`. Архитектуру показывает `uname -m`: `x86_64` → amd64, `aarch64` → arm64. Бинарники статические, собраны с `CGO_ENABLED=0`. AMD64 проверена запуском; ARM64 собрана и проверена как ELF, но не запускалась на ARM-оборудовании.

Порядок работы:

1. Нажмите **Открыть изображение** и выберите PNG/JPEG/GIF. Диалог позволяет переходить по папкам; имена с кириллицей можно выбирать мышью. **Демо** возвращает встроенный пример.
2. Укажите угол (по умолчанию 30°) и ось отражения. Положительный угол направлен по часовой стрелке в экранной системе координат.
3. Выполните аффинное преобразование, восстановление и нелинейное преобразование отдельно либо кнопкой **Выполнить всё**.
4. Выберите каталог вывода и сохраните все три результата или отдельную картинку. По умолчанию GUI сохраняет в `output` рядом с каталогом `bin`.

Восстановление читает аффинный результат и использует матрицу именно выполненного преобразования. Изменение поля угла без нового выполнения аффинной операции не подменяет сохранённую матрицу.

## Консольный режим

```bash
./bin/lab6-linux-amd64 -mode batch -source images/source.png -out output -angle 30 -axis vertical
./bin/lab6-linux-amd64 -mode gui -source images/source.png
./bin/lab6-linux-amd64 -mode demo -out demo-output
./bin/lab6-linux-amd64 -h
```

Ось: `vertical` или `horizontal`. Угол: конечное число от −360 до 360. `batch` требует `-source`; `demo` без источника создаёт встроенный рисунок. Выходные файлы: `affine.png`, `restored.png`, `nonlinear.png`, `metrics.json`; `demo` дополнительно сохраняет `source.png`. Повторное сохранение заменяет одноимённые результаты; выбирайте отдельный каталог для нового опыта. В GUI `metrics.json` не записывается.

## Что именно вычисляется

Сначала поворот относительно центра `((W−1)/2, (H−1)/2)`, затем отражение относительно выбранной центральной оси. Масштабирование из примера варианта 0 к варианту 8 не относится. Холст сохраняет размер источника. Незаполненные вследствие выхода за границу пиксели белые.

Каждый пиксель назначения получает RGB ближайшего пикселя источника по **обратному отображению**. Это способ реализации прямого геометрического преобразования без дыр. Для обратного геометрического преобразования источник — уже преобразованный растр; исходное изображение не подставляется. Отсечение и повторное округление теряют информацию, поэтому восстановление не обязано совпадать с исходником.

Нелинейная формула используется **буквально, в пиксельных координатах**, без нормирования или подгонки масштаба: выборка `x′ = i^(3/5), y′ = j`. При ширине 640 максимальное `x′ ≈ 48,228`, поэтому результат растягивает первые 49 столбцов исходника. Это ожидаемое следствие формулы и фиксированного размера холста. Нелинейный результат вычисляется из исходника независимо от аффинного.

Ввод: PNG/JPEG/GIF (первый кадр), стороны до 4096, до 16 000 000 пикселей, файл до 32 МиБ. Цвет: непрозрачный RGB по 8 бит; прозрачность накладывается на белый фон, 16-битные компоненты приводятся к 8 битам. Вывод — PNG; запись каждого PNG производится через временный файл и переименование.

Для приложенного примера 640×420, 30°, `vertical`:

| Операция | Отсчёты внутри источника | За границей источника |
|---|---:|---:|
| Аффинная | 219730 | 49070 |
| Восстановление | 219730 | 49070 |
| Нелинейная | 268800 | 0 |

MAE восстановления: **20,619776785714286** на RGB-шкале 0–255. Счётчик выхода за границы не равен числу всех белых пикселей: белый может уже присутствовать в источнике или аффинном растре.

## Состав работы

- `bin/` — готовые статические бинарники amd64 и arm64.
- `cmd/lab6/`, `internal/raster/`, `internal/desktop/` — полный Go-код приложения и тесты.
- `vendor/`, `go.mod`, `go.sum` — зафиксированные зависимости для сборки без сети.
- `images/` — исходный рисунок, три результата, параметры и метрики.
- [report/report.docx](report/report.docx), [report/report.pdf](report/report.pdf) — отчёт; [report/report.md](report/report.md) — текстовая версия.
- `report/algorithm-*.svg` и `.png` — блок-схемы; `report/interface.png` — снимок реального окна.
- `tools/` — оформление и проверка документов; эти Python-скрипты приложению не нужны.
- `validation/` — протоколы проверок; `SHA256SUMS` — контрольные суммы.
- `reference/lab6-manual-pages-115-128.pdf` — неизменённые страницы задания, таблицы вариантов и требований к отчёту.
- `reference/TSOS_Lab4_Variant7.docx` — только образец оформления, не источник задания по графике.
- `third_party/` и `internal/desktop/assets/FONT-LICENSE.txt` — лицензии зависимостей и шрифта.

## Сборка разработчиком

Только для изменения кода нужен Go (модуль объявляет Go 1.22; готовые файлы собраны Go 1.27.3). Из папки `lb6`:

```bash
CGO_ENABLED=0 go test -mod=vendor ./...
CGO_ENABLED=0 go vet -mod=vendor ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -mod=vendor -trimpath -ldflags='-s -w' -o bin/lab6-linux-amd64 ./cmd/lab6
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -mod=vendor -trimpath -ldflags='-s -w' -o bin/lab6-linux-arm64 ./cmd/lab6
```

X11-тест без `DISPLAY` явно пропускается. Для полной проверки нужен X11 либо Xvfb. В этой среде выполнены все **9 тестов**, включая окно готового бинарника:

```bash
DISPLAY=:99 LAB6_GUI_BINARY="$PWD/bin/lab6-linux-amd64" LAB6_GUI_CAPTURE="$PWD/report/interface.png" CGO_ENABLED=0 go test -mod=vendor -count=1 -v ./...
```

`:99` здесь — ранее запущенный Xvfb, а не универсальный адрес рабочего стола. Тест отправляет события мыши, открывает файл, сохраняет PNG и сравнивает пиксели. Снимок считывается с X-сервера. Готовый процесс запускается с `PATH=/nonexistent`; консольный процесс дополнительно проверен через `strace` (нет дочерних команд и сетевых подключений). Попытка отдельного контейнерного теста не удалась из-за запрета user namespace; это не выдаётся за успешную проверку изоляции.

Оформление отчёта требует Python с `python-docx`, Pillow, PyMuPDF, Inkscape и LibreOffice, а также установленного Times New Roman:

```bash
python3 tools/build_diagrams.py
python3 tools/build_report.py
soffice --headless --convert-to pdf --outdir report report/report.docx
python3 tools/check_report.py
```

В подготовленной облачной среде перед экспортом установите `FONTCONFIG_FILE=/workspace/document-tools/fontconfig/fonts.conf` и `XDG_CACHE_HOME=/workspace/.cache`. Использованные шрифты проверены; отдельные математические символы PDF могут использовать шрифт подстановки. После изменения кода пересоберите бинарники, результаты, отчёт, контрольные суммы и архив.
