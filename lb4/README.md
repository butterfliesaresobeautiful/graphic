# ЛБ4 — Растеризация окружностей

**Индивидуальный номер 28; максимальный вариант 20; 28 % 20 = 8.**
Задание варианта: **«Вывести треугольник Рёло заданной ширины»**
Требуется четыре способа построения: уравнение окружности, параметрическое уравнение, Брезенхем и готовые графические средства.

## Запуск без Go

Скачайте и распакуйте [dist/lab4-variant8.zip](dist/lab4-variant8.zip). В распакованной папке `lab4-variant8` выполните:

```bash
chmod +x bin/lab4-linux-amd64
./bin/lab4-linux-amd64
```

В репозитории те же команды выполняются из `lb4`. Откроется отдельное настольное окно. **Go устанавливать не нужно.** Бинарник статический, `CGO_ENABLED=0`; шрифт и Go-зависимости встроены. Python, браузер, GTK/Qt и интернет приложению не нужны.

Требуется обычный графический сеанс Linux **X11 либо Wayland с XWayland**, корректный `DISPLAY`, TrueColor с 32-битным хранением пикселя LSBFirst. Это обычная конфигурация Linux desktop; при несовместимом формате программа выдаст сообщение. Запускайте от своего пользователя без `sudo`, чтобы сохранить доступ к графическому сеансу.

## Работа в окне

1. Оставьте белый холст или нажмите **Открыть фон…** для PNG/JPEG/GIF. Диалог позволяет переходить по каталогам и выбирать имена с кириллицей мышью.
2. Для варианта 8 оставьте **Фигура: Треугольник Рёло**. Введите ширину, центр X и центр Y. По умолчанию: ширина 280, центр (320;240), холст 640×480.
3. Нажмите **Построить 4 метода**. Четыре панели показывают результаты. Изменение поля само по себе не перестраивает фигуру; сохранение записывает последние построенные результаты.
4. Кнопкой **Вид** переключайте четыре метода, наложение/карту различий/фон и увеличенный участок. Уменьшенные превью фильтруются для видимости тонких линий; PNG сохраняет исходные пиксели без сглаживания.
5. Выберите каталог вывода и нажмите **Сохранить результаты**. По умолчанию GUI использует `output` рядом с папкой `bin`.

**Ширина Рёло равна радиусу каждой из трёх дуг.** Поле **R окруж.** используется в дополнительном режиме **Окружность**, где радиус и центр задаются независимо, согласно общему заданию методички. Это дополнительный режим; сдаваемый вариант — треугольник Рёло.

Поля редактируются клавиатурой; клик выделяет прежнее значение для замены, доступны Ctrl+A, Backspace/Delete, Tab и Enter. Esc закрывает диалог. Программа сообщает об ошибках чисел, файлов, доступа и сохранения.

## Консольный запуск

```bash
./bin/lab4-linux-amd64 -mode batch -size 280 -cx 320 -cy 240 -out output
./bin/lab4-linux-amd64 -mode batch -source фон.png -size 280 -out output
./bin/lab4-linux-amd64 -mode batch -shape circle -radius 140 -out circle-output
./bin/lab4-linux-amd64 -h
```

**Для полного сравнения в batch тоже нужен X11/XWayland:** четвёртый способ реально вызывает готовый примитив X11 `PolyArc`. В стандартной библиотеке Go встроенной функции окружности нет. Программа не заменяет этот способ собственной копией Брезенхема. `batch` не показывает окно, но использует сервер для растеризации на отдельном Pixmap. На сервере без экрана разработчик может запустить Xvfb; на компьютере преподавателя используется имеющийся графический сеанс.

Параметры `-width`, `-height` задают белый холст. При `-source` размеры берутся из файла. Отрицательные координаты допускаются в указанных ниже пределах: части контура за холстом отсекаются. Полностью невидимая фигура даёт пустые маски.

Результаты:

| Файл | Содержание |

| `equation.png` | Уравнение окружности и симметрия октантов |
| `parametric.png` | Параметрическое уравнение и соединение соседних отсчётов |

Повторный запуск заменяет одноимённые результаты. Для нового опыта выбирайте новый каталог. Проверяется совпадение выходного пути с загруженным фоном, в том числе существующие файловые ссылки. Каждый PNG записывается через временный файл и переименование; весь набор файлов не является одной атомарной транзакцией.

## Геометрия и алгоритмы

Центр `(x₀,y₀)` — центроид исходного равностороннего треугольника. В экранной системе Y направлена вниз:

```text
A = (x₀,     y₀ − w/√3)
B = (x₀−w/2, y₀ + w/(2√3))
C = (x₀+w/2, y₀ + w/(2√3))
```

Центры трёх дуг — A, B, C, радиусы равны w, диапазоны экранных углов соответственно 60…120°, 300…360°, 180…240°. Это граница пересечения трёх дисков радиуса w.

- Уравнение: `y = round(sqrt(R²−x²))` в одном октанте, восемь симметричных точек. Включается округлённая диагональная точка; сканирование всей четверти с большими скачками Y не используется.
- Параметрическое: `N=ceil(R·β·π/180)`, равномерный шаг по углу с длиной дуги не больше 1 пикселя, оба конца включены. Соседние округлённые отсчёты соединяются целочисленным отрезком.
- Брезенхем: `x=0, y=R, d=3−2R`; при `d<0` — `d+=4x+6`, иначе `d+=4(x−y)+10, y--`; затем `x++`. Справа используются старые x,y. Целочисленность относится к ядру; отбор дуг и перенос используют вещественные координаты.
- X11: `PolyArc` с тонкой линией без сглаживания, квадратом 2R и углами 1/64 градуса. Центры округляются до целых, направление углов инвертируется относительно экранного. Растр считывается с X-сервера. Общие вершины добавляются через `PolyPoint`, как и в собственных методах.

Сравниваются **маски контуров**, независимо от исходного фона. Чёрные пиксели загруженной картинки не искажают статистику. XOR считает обе стороны различия, а не разность количества пикселей. Наложение использует синий/оранжевый/зелёный/фиолетовый для четырёх методов и средний цвет при частичном совпадении; точные различия видны в карте и числах.

В приложенном примере 640×480, w=280, центр (320;240):

| Метод | Пикселей | XOR с Брезенхемом |
|---|---:|---:|
| Уравнение | 793 | 0 |
| Параметрический | 832 | 317 |
| Брезенхем | 793 | 0 |
| X11 | 793 | 0 |

Объединение — 971 позиция, пересечение — 654, различающихся — 317. Параметрический метод выбирает другую лестницу контура. Совпадение остальных методов подтверждено для этого опыта; оно не объявляется универсальным для всех размеров и X-серверов. Для окружности R=140: 792/824/792/792 пикселя, XOR параметрического с остальными — 80. Все данные получены фактическим запуском.

Входные ограничения: стороны 1…4096, площадь до 16 000 000 пикселей, файл до 32 МиБ; ширина и радиус 1…2048; координаты −4096…4096. PNG/JPEG/GIF декодируются в 8-битный непрозрачный RGB, прозрачность накладывается на белый фон, GIF читается по первому кадру. 16-битные компоненты приводятся к 8 битам.

## Отчёт и состав комплекта

- `cmd/lab4`, `internal/` — Go-код и тесты; `bin/` — готовые ELF.
- `images/` — реальные результаты Рёло; `images/circle/` — дополнительная окружность.
- `report/` — DOCX/PDF/Markdown, схемы SVG/PNG, чертёж геометрии, настоящие снимки окна.
- `reference/` — исходные страницы методички.
- `vendor/`, `go.mod`, `go.sum` — зависимости для сборки без сети.
- `third_party/`, `internal/desktop/assets/FONT-LICENSE.txt` — лицензии.
- `validation/` — протоколы; `SHA256SUMS` — контрольные суммы.
- `tools/` — подготовка документов и архива, не часть исполняемого приложения.

## Сборка и проверка разработчиком

Только для изменения кода нужен Go. Модуль объявляет Go 1.22, готовые бинарники собраны Go 1.27.3:

```bash
CGO_ENABLED=0 go test -mod=vendor ./...
CGO_ENABLED=0 go vet -mod=vendor ./...
CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -mod=vendor -trimpath -ldflags='-s -w' -o bin/lab4-linux-amd64 ./cmd/lab4
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go build -mod=vendor -trimpath -ldflags='-s -w' -o bin/lab4-linux-arm64 ./cmd/lab4
```

Без `DISPLAY` тесты X11 и полного batch явно пропускаются. В этой среде выполнены все **10 тестов**, включая готовый бинарник на Xvfb:

```bash
DISPLAY=:99 LAB4_GUI_BINARY="$PWD/bin/lab4-linux-amd64" LAB4_GUI_CAPTURE="$PWD/report/interface.png" LAB4_GUI_COMPARISON="$PWD/report/interface-comparison.png" CGO_ENABLED=0 go test -mod=vendor -count=1 -v ./...
```

`:99` — адрес предварительно запущенного тестового Xvfb. На рабочем столе используется свой `DISPLAY`. Тест отправляет реальные события X11, открывает файл, вводит ширину клавиатурой, строит и сохраняет результаты, сравнивает RGB, снимает пиксели окна с сервера. Дочерний процесс имеет `PATH=/nonexistent`. Отдельный запуск под `strace` подтвердил отсутствие дочерних команд: нужны только соединения с локальным X-сервером. Это не выдаётся за тест отдельного контейнера без Go.

Оформление документов требует Python, python-docx, Pillow, PyMuPDF, matplotlib, Inkscape, LibreOffice и Times New Roman:

```bash
python3 tools/build_diagrams.py
python3 tools/build_geometry.py
python3 tools/build_report.py
soffice --headless --convert-to pdf --outdir report report/report.docx
python3 tools/check_report.py
DISPLAY=:99 python3 tools/package.py
```

В подготовленной облачной среде экспорт выполняется с `FONTCONFIG_FILE=/workspace/document-tools/fontconfig/fonts.conf XDG_CACHE_HOME=/workspace/.cache`. Основной шрифт PDF — настоящий Times New Roman; отдельные математические символы могут использовать подстановку. После изменения кода обновите бинарники, изображения, тестовые протоколы, листинги, контрольные суммы и архив.
